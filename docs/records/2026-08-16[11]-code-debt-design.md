# Волна 8: код-долг

Последняя волна программы и **единственная, меняющая код, а не текст**.
Значит единственная, где могут сдвинуться калиброванные полосы
`memory_guard` и `complexity_guard`, и единственная, где меняются
выдаваемые байты — ровно один случай, и он прошёл через решение владельца.

Четыре находки ревью проверены по живому коду. Две подтвердились как
описаны, две оказались **уже**, и одна из них по ходу превратилась в
вопрос о публичной поверхности.

## 1. L7 — коллизия хешей у цветов

**Что сейчас.** `Color16` и `Color256` держат поле одного и того же
перечисления — у обоих `final Colors color;` — и оба считают
`hashCode` как `color.hashCode`. Значит цвета разных классов с одним
значением делят хеш, при том что `==` их разводит (`other is Color16`,
`other is Color256`).

Пробник на живом коде:

```
Color16.red  hash=4552149 id=?Red
Color256.red hash=4552149 id=?256Red
equal? false   same hash? true
Style equal? false  same hash? true
```

Коллизия систематическая — по одной на каждое значение `Colors` — и
протекает в `State.hashCode`, который складывает цвета через
`Object.hashAll`.

**Это не дефект корректности.** Тот же пробник:

```
Set holds both: 2
Map holds both: 2  lookup a=sixteen b=two-fifty-six
```

`==` разводит объекты внутри бакета, поэтому коллекции отвечают верно.
Цена — только в том, что коллидирующие записи ложатся в один бакет.
Формулировать надо честно: это качество хеша, а не сломанное поведение.

**Решение.** Каждый из трёх цветовых классов солит хеш собственным типом:

```dart
int get hashCode => Object.hash(Color16, color);     // было color.hashCode
int get hashCode => Object.hash(Color256, color);    // было color.hashCode
int get hashCode => Object.hash(ColorRgb, _value);   // было _value.hashCode
```

`ColorRgb` включён не потому, что он с кем-то коллидирует сегодня, а
чтобы правило было одно на три класса: иначе следующий, кто добавит
четвёртый цвет, скопирует ту из двух форм, которая попадётся.

**Чего в засолку не входит.** Поле `_target` не участвует ни в `==`, ни в
хеше — и не должно: равные объекты обязаны давать равный хеш, а `==`
`_target` игнорирует намеренно. Волна этого не трогает.

**Что тесты об этом говорят.** Литеральных значений хеша не пинит ни один
тест; есть только относительные утверждения — `state_equality_contract_test`
требует, чтобы `Stack` и `Style` одного состояния давали равный хеш. Оба
несут один и тот же экземпляр цвета, поэтому засолка их не разводит.

## 2. L8 — мёртвый параметр

**Что сейчас.** В `lib/src/parsing/state/state.dart`:

```dart
String _color(int offset, int highOffset, ExtendedColor color) =>
    switch (color) {
      Color256(:final index) => '$CSI${offset + 8};$COLOR_256;$index$SGR',
      ColorRgb(:final r, :final g, :final b) =>
        '$CSI${offset + 8};$COLOR_RGB;$r;$g;$b$SGR',
    };
```

`highOffset` не читается ни одной ветвью. Три вызова: `_color(30, 90, …)`,
`_color(40, 100, …)` и `_color(50, 0, …)` — последний передаёт `0`, число,
не значащее ничего.

Соседний `_colorIndex(offset, highOffset, …)` оба параметра использует
(`color.index(offset, highOffset)`), и именно поэтому мёртвый близнец
выглядел живым.

**Решение.** Параметр убирается, три вызова теряют аргумент. Поведение не
меняется вовсе — параметр не читался.

## 3. `skipReset` и `skipSet` уходят из публичной сигнатуры

Это решение владельца, принятое по ходу разбора L12, и оно шире самой
находки.

**Что сейчас.** `State.transitTo` публичен и объявляет два именованных
флага:

```dart
String transitTo(S other, {bool skipSet = false, bool skipReset = false});
```

Оба несут нагрузку внутри пакета, так что убрать их совсем нельзя:

| место | флаг | зачем |
|---|---|---|
| `style.dart:674` | `skipReset: true` | `Style.open` — коды от цветов терминала к стилю |
| `sgr_residual.dart:141,152` | `skipReset: true` | переход от `terminalColors` к базе residual |
| `parser.dart:769` | `skipSet: true` | хвост среза |

Но публичными они быть не обязаны. В `README.md`, `README.ru.md`,
`example/` и `doc/` они не встречаются ни разу; из тестов флаг используют в
одном месте (`test/substring_open_state_test.dart:26`). Полезный
пользователю случай уже завёрнут в геттер: `Style.open` — это буквально
`terminalColors.transitTo(this, skipReset: true)`, а `Style.close` — сброс.
Наружу торчала внутренняя идиома при том, что её удобная форма рядом.

**Решение.** Публичным остаётся

```dart
String transitTo(S other);
```

а флаги переезжают в

```dart
@internal
String transitToPart(S other, {bool skipSet = false, bool skipReset = false});
```

`transitTo` делегирует ему с обоими флагами `false`. Прецедент для
`@internal` на члене публичного класса в репозитории есть — он стоит на
`Color16.on`.

Три внутренних места и один тест переходят на `transitToPart`.

**Почему сейчас.** `4.0.0` не опубликована. Сузить публичную сигнатуру
бесплатно можно только до тега; после — это breaking change.

**Оговорка, которую нельзя пропустить.** `check_entry_points.dart` этого
**не заметит**: снапшот `tool/entry_point_names.json` держит только
top-level имена — `transitTo` в нём не встречается вовсе, а `1646` считает
классы и функции, не члены. Значит:

- число ворот `1646` не сдвинется, `--update-snapshot` не нужен;
- правка публичной сигнатуры проходит мимо ворот и проверяется глазами.

Второе — находка, а не задача этой волны: закрыть её значило бы пинить
сигнатуры членов, то есть третий инструмент и отдельный заход. Пишется в
`docs/handoff.md`.

## 4. L12 — лишний байт, который теперь можно просто убрать

**Что сейчас.** `CSI 22` снимает жирность и тусклость вместе, поэтому при
снятии одной из пары вторую надо выставить обратно:

```dart
if (jointIntensityReset) ...[
  if (other.isBold) '1',
  if (other.isDim) '2',
] else if (!skipSet) ...[
  if (!isBold && other.isBold) '1',
  if (!isDim && other.isDim) '2',
],
```

В совместной ветви условие не смотрит на текущее состояние — и правильно
не смотрит, пока сброс выдаётся: он снёс оба. Но при `skipReset: true`
сброса нет, и повтор становится пустым байтом.

Пробник, пять переходов:

| переход | `skipReset: true` | нужен? |
|---|---|---|
| bold+dim → bold | `CSI 1` | **нет**, жирность и не снималась |
| bold+dim → dim | `CSI 2` | **нет** |
| bold → dim | `CSI 2` | да, тусклости не было |
| dim → bold | `CSI 1` | да |
| bold+dim → plain | пусто | — |

**Внутри пакета эта ветка недостижима.** Все три внутренних вызова
`skipReset: true` идут от `Style.terminalColors`, у которого
`isBold = false` и `isDim = false` (снято пробником), поэтому
`jointIntensityReset` там всегда ложно. Лишний байт доставался только
тому, кто звал публичный `transitTo(skipReset: true)` сам.

**Почему решение владельца понадобилось и почему оно теперь простое.**
Пока флаг был публичным, повторный `1` можно было прочесть как часть
контракта: дартдок говорит, что `skipReset` убирает коды, которые
*снимают* свойства, а повторная установка — не снятие. Вызывающий,
выдавший `CSI 22` сам, вправе был рассчитывать на возврат выжившей
половины. Убрать байт значило бы тихо сломать такой сценарий.

С уходом флага внутрь обещания не остаётся, и решать нечего: сброса не
было — восстанавливать нечего.

**Решение.** В совместной ветви при `skipReset` берётся обычное условие:

```dart
if (jointIntensityReset && !skipReset) ...[
  if (other.isBold) '1',
  if (other.isDim) '2',
] else if (!skipSet) ...[
  if (!isBold && other.isBold) '1',
  if (!isDim && other.isDim) '2',
],
```

Форму условия план обязан снять пробником, а не принять отсюда: здесь
показано намерение, а точная запись должна пройти по всем пяти переходам
таблицы выше и по обеим ногам `skipSet`.

## 5. L23 — решать до постройки

**Что сейчас.** `commitFunction` в
`lib/src/parsing/parser/entities/sgr.dart` строит для **каждой** SGR-функции:

```dart
final rawParameters = _rawParams.sublist(_operationStart, _index + 1).join(';');
final operation = _SgrOperation(
  string: '$CSI$rawParameters$SGR',
  function: function,
  state: state.toStyle(),
);
residual = _advanceSgrResidual(residual, _operationBefore, operation);
```

То есть `sublist` + `join` + интерполяция строки, плюс `state.toStyle()` —
который для `Style` бесплатен (`toStyle() => this`), а для `Stack` строит
целый новый `Style` из полутора десятков полей.

А `_advanceSgrResidual` выбрасывает операцию целиком в двух случаях из
трёх:

1. `_isFullSgrReset(operation.function)` → `null`;
2. `residual == null && !operation.isUnknown` → `null`.

Оба условия — чистые switch по `function` (`_isFullSgrReset`,
`_isUnknownSgrFunction`), вычислимые **до** всякой постройки. Обычный
разбор — это как раз известные функции при пустом residual, то есть
второй случай.

**Решение.** Один источник истины, которым пользуются оба места:

```dart
/// Whether an operation carrying [function] would be kept ...
bool _residualKeeps(_SgrResidual? residual, SgrFunction? function) =>
    !_isFullSgrReset(function) &&
    (residual != null || function == null || _isUnknownSgrFunction(function));
```

`_advanceSgrResidual` делает его своей первой проверкой вместо нынешних
двух ветвей, а `commitFunction` ставит на нём охрану и строит операцию
только внутри неё; иначе просто `residual = null`.

**Почему не замыкание.** Напрашивается передать `_SgrOperation Function()`
и звать лениво. Так решение осталось бы в одном месте само собой, но
замыкание — это аллокация на каждый вызов в горячем пути, то есть можно
съесть выигрыш ради красоты. Общий предикат даёт ту же единственность
решения без аллокации.

**Почему не проверка на месте вызова.** Продублировать условие в
`commitFunction` и оставить `_advanceSgrResidual` как есть — это две копии
одного решения, которые разойдутся. Ровно этот дефект волна 7 чинила в L9.

**Второй вызывающий не трогается.** `_advanceSgrResidual` зовут из двух
мест; второе — `csi.dart:47`, непрозрачная ветвь, где `function == null`,
операция всегда сохраняется и строить её всё равно надо.

## Измерение

`benchmark/parser_benchmark.dart` написан ровно для этого: «run it before a
change and after it, and compare the two». Заявленные ревью **~15 %**
проверяются, а не принимаются.

**База снимается непосредственно перед правкой, на том же дереве и в том
же состоянии машины.** Числа из этой спеки для сравнения не годятся:
машина, на которой волна делается, уходит в своп (в волне 7 `dart test`
дважды убит OOM-killer'ом), и число, снятое час назад, сравнивать не с чем.
Порядок: замер до → правка L23 → замер после → в отчёт обе колонки.

`complexity_guard` меряет **форму** роста, а не цену, поэтому ускорение
константы он не покажет и показать не должен: его дело — остаться в полосе.

объяснить, а не подогнать.** За семь волн выведенное рассуждением
оказывалось неверным шесть раз.

## Порядок работ

Ветка `fix/code-debt`, пять коммитов:

1. `fix:` L7 — засолить хеши типом;
2. `refactor:` L8 — убрать мёртвый параметр;
3. `refactor:` сокрытие флагов за `transitToPart`;
4. `fix:` L12 — убрать лишний байт;
5. `perf:` L23 — решать до постройки.

Порядок не случаен: сокрытие флагов идёт **до** L12, потому что именно оно
делает правку байта свободной от обещаний.

Дальше по обычному: пуш ветки, **зелёный CI на обеих ногах**, `git merge
--no-ff` в `main`, `git push origin main`. Отчёт волны и ротация
`docs/handoff.md` — тем же заходом. Этой волной программа правок по ревью
заканчивается, и handoff должен сказать, что осталось: только решения
владельца о публикации и теге.

## Чего эта волна не делает

- **Не пинит сигнатуры членов.** То, что `check_entry_points` их не видит,
  записывается находкой; закрыть — отдельный заход с третьим инструментом.
- **Не трогает `_target` в равенстве цветов.** Он исключён из `==`
  намеренно, и волна разбирается с хешем, а не с равенством.
- **Не меняет `complexity_guard`.** Ускорение константы его полосы не
  двигают, и подгонять их под новый замер нельзя.
- **Не публикует и не бампает версию.** Это решение владельца, и оно не
  менялось с 2026-08-05.
