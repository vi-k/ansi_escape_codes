## Цели и критерии готовности

Берутся четыре корректность-находки ревью. Ветка `fix/review-correctness`
от main (`bb2f851`). Один фикс — один коммит: red-тест, фикс и строка
CHANGELOG (где фикс меняет поведение — H1, H2, M1) — вместе;
conventional-префиксы; версия не трогается.
Порядок коммитов: **M8 → H1 → M1 → H2** (обоснование в разделе 2).

Фикс считается готовым, когда:

1. все существующие тесты зелёные **без правок самих тестов**;
2. `dart analyze --fatal-infos` и `dart format` чистые;
3. red-green соблюдён: падение нового теста зафиксировано до фикса
   (для M8 вместо этого — sabotage-проверка, см. раздел 2);
4. документация, которую фикс задевает (dartdoc, README, CHANGELOG),
   правится в том же коммите.

## Раздел 1 — архитектура фиксов

### H1 — порядок восстановления режимов терминала

`lib/src/utils/current_cursor_pos.dart:43-47`. Сейчас восстановление идёт
каскадом `..echoMode = keep ..lineMode = keep`; на Windows `echoMode`
можно включить только при уже включённом `lineMode`, поэтому в обычной
интерактивной консоли первое же присваивание бросает, каскад рвётся и
терминал остаётся в raw-режиме.

Восстановление делается зеркально отключению — сначала `lineMode`, потом
`echoMode` — и вложенным try/finally, чтобы падение одного присваивания
не срывало второе:

```dart
} finally {
  try {
    stdin.lineMode = keepLineMode;
  } finally {
    stdin.echoMode = keepEchoMode;
  }
}
```

Порядок отключения (`echoMode = false`, затем `lineMode = false`) уже
согласован с ограничениями Windows и не меняется.

### H2 — направленный сдвиг к границе суррогатной пары

`lib/src/parsing/parser/parser.dart`, `_seamAt`. Позиции публичного API —
UTF-16 code units, и позиция может указать между половинами суррогатной
пары: `Parser('𝄞abc').insertBefore(1, 'X')` вклинивает `X` между `D834`
и `DD1E`, строка перестаёт быть валидным UTF-16.

Решение (зафиксировано пользователем): позиция внутри пары сдвигается к
границе пары по направлению вставки — в `insertBefore` к началу, в
`insertAfter` к концу. Вставка никогда не разрывает пару входа.

Реализация: в `_seamAt`, найдя место среза внутри куска текста
(`offset = pos - plainPos` в code units куска), проверить
`offset >= 1 && isHigh(u[offset - 1]) && isLow(u[offset])`; при
попадании в середину пары — самоперевызов с `after ? pos + 1 : pos - 1`.
Глубина рекурсии ровно 1: после сдвига на единицу позиция стоит на
границе пары и проверка второй раз не срабатывает (в том числе на
патологических входах из одиноких суррогатов, см. раздел 2).

Пары, разорванные escape-кодом между кусками, — это одинокие суррогаты
самого входа; они не распознаются и не трогаются: библиотека не чинит
невалидный вход.

Документационная часть того же коммита: явная code-unit-семантика
`length`/`pad*`/`substring` — «как у `String`»; переформулировка README
«counts what is seen»; оговорка «валидный UTF-16, не графемы»;
CHANGELOG Fixed.

### M1 — `substring` дописывает закрытие гиперссылки

`lib/src/parsing/parser/parser.dart`, `substring` (289-360).
`substring(0, maxLength: 3, close: true)` на строке со ссылкой возвращает
хвост с открытой OSC 8 — всё, что программа напечатает дальше, кликабельно
и ведёт на чужой URL. Ровно от этого `_insert` защищается через
`_closeLink`.

Решение: отслеживается ссылка, **эмитированная в буфер** (не состояние
входа): при записи `Link` в вывод — с непустым url ссылка открыта, с
пустым закрыта. В конце, при `close: true` и открытой ссылке, перед
финальным `transitTo` дописывается `linkClose` — зеркально `_insert`.

Срез, начавшийся внутри ссылки, её открытия не эмитит — и закрытие не
дописывается: открыл не срез, не ему и закрывать (согласуется с
`_insert`, который закрывает только то, что открыл вставленный текст).
`close: false` оставляет ссылку открытой — как оставляет открытым стиль;
поведение сохраняется и документируется.

### M8 — свип таблиц цветов: тесты и есть фикс

Рукописные таблицы (`styles.dart` — 783 static const,
`style_colors.dart` — 512 геттеров, `ready_to_use/sgr/colors256/*` —
именованные константы) фактически не проверяются: опечатка индекса или
слота уезжает в релиз молча — класс бага, дважды чиненный в этом самом
релизе. Два механизма по форме поверхности:

- **Mirrors-свип** (тесты и так на VM). `Styles`: ожидаемые имена
  строятся из `Colors.values` (15 свойств + `red`/`bgRed`/`underlineRed`
  на каждый из 256 цветов), член ищется через `ClassMirror`, значение
  сверяется с формулой (`Style` с соответствующим слотом и
  `Color256.on(index)`); полнота — счётчик сходится с 783. Тем же
  способом: статики `Color256`; top-level `fg256*`/`bg256*`/
  `underline256*` против функций `fg256(i)`/`bg256(i)`/`underline256(i)`.
- **Source-проверка** для extension `StyleColors` (mirrors расширения не
  видят): тест читает `style_colors.dart` и проверяет regex-ом каждое
  объявление — `Style get <name> => foreground(Color256.<name>);` и
  `bg<Name> => background(Color256.<name>)`; правило «имя ↔ слот + цвет
  тела», полнота (512 = 256 fg + 256 bg), отсутствие дублей.

Точная грамматика имён `Styles` закрепляется в плане по фактическому
`styles.dart` — она видна из файла механически.

## Раздел 2 — тесты, эквивалентность, порядок коммитов

### H1

Red-green. Новый файл `test/current_cursor_pos_windows_test.dart`;
существующий `current_cursor_pos_test.dart` не редактируется (фейк
дублируется — паттерн проекта). Windows-фейк stdin усиливает `_FakeStdin`
ограничениями из документации SDK:

- `echoMode = true` при `lineMode == false` → бросает;
- `lineMode = false` при `echoMode == true` → бросает (пиннит и порядок
  отключения).

RED: на текущем каскаде тест «happy path возвращает позицию и оба режима
восстановлены» падает — восстановление начинается с `echoMode` при ещё
выключенном `lineMode`. GREEN: вложенный try/finally из раздела 1.
Тесты: happy path; timeout-путь (режимы восстановлены и на
Windows-фейке). Эквивалентность на POSIX: те же два присваивания в другом
порядке; 12 существующих тестов остаются зелёными без правок.

### H2

Новый файл `test/parser_insert_surrogates_test.dart`:

- оба mid-pair-случая: `insertBefore(1, 'X')` на `𝄞abc` → `X𝄞abc`;
  `insertAfter(1, 'X')` → `𝄞Xabc`;
- разорванная кодом пара (одинокие суррогаты входа, например
  `'\uD834${fgRed}\uDD1E'`) — поведение не меняется, пиннится как есть;
- патологический вход `'\uD834𝄞'` — сдвиг не зацикливается и
  не уходит глубже одного шага;
- не-BMP-корпус: строки с эмодзи/CJK/𝄞 вперемешку с escape-кодами,
  вставка на каждой позиции; инварианты: выход — валидный UTF-16 везде,
  где вход был валиден, и выход равен входу со вставкой в сдвинутой
  позиции (дифференциальная сверка).

RED: mid-pair-тесты падают на текущем коде (`X` между `D834` и `DD1E`).
GREEN: самоперевызов `_seamAt`. Документационная часть поведения не
меняет и отдельных тестов не требует.

### M1

Новый файл `test/parser_substring_links_test.dart` (рядом с паттерном
`parser_substring_trailing_codes_test.dart`):

- RED-случай: срез, кончающийся внутри открытой ссылки, при

- срез, начавшийся внутри ссылки (открытие не эмитировано), — закрытие

- `close: false` — ссылка остаётся открытой (пиннится и документируется);

Эквивалентность: `parser_substring_differential_test.dart` и

### M8

Red-green в обычном смысле нет — тест и есть фикс. Вместо него
sabotage-проверка при разработке: временно портится по одной записи
каждого вида (константа `Styles`, геттер `StyleColors`, константа
`fg256*`), свип обязан упасть, правка откатывается. В репозиторий
sabotage не попадает; в сообщении коммита фиксируется, что проверка
выполнялась.

### Порядок коммитов

**M8 → H1 → M1 → H2**:

1. **M8** — страховочная сетка на таблицы ложится первой и ни от чего
   не зависит;
2. **H1** — изолированная утилита, парсера не касается;
3. **M1** — локальная правка `substring`;
4. **H2** — самый широкий коммит (парсер + dartdoc + README +
   CHANGELOG), идёт последним.

Исполнение — как в перф-заходе: writing-plans → план с точным кодом →
subagent-driven-development (свежий имплементер на задачу, ревью после
каждой, финальное whole-branch-ревью), затем PR в main. Публикация 4.0.0
и тег v4.0.0 — после закрытия захода, решением пользователя.
