## L9 оказался глубже, чем «девять чисел»

Каждый член `ControlFunctionsSGR` подписан числом в хвостовом комментарии
(`bgBlack, // 30`), и рядом, в `lib/src/ansi/sgr.dart`, лежит
`const int BG_BLACK = 40;`. То есть **комментарий — переписанная от руки
копия константы, которая уже есть в коде.** Копия разошлась с источником:
восемь фоновых цветов несли коды переднего плана, а `bgHighBlue` — `1010`
вместо `104`, что похоже на промах пальца, а не на стандарт.

Сверка всех членов пробником дала ровно девять расхождений — ревью нашло
всё, ничего сверх. Но раз источник существует в коде, копию можно держать
к нему, и это сделано: `test/sgr_numbering_test.dart` читает число с
члена, читает имя константы из его же строки `/// See [sgr.X] and
[sgr.Y].` и требует совпадения. Покрыты все **73** члена с числом.

Правило извлечения константы — «последнее UPPER_SNAKE-имя в ближайшей
строке `See`». Двух форм оказалось достаточно: обычная называет одну
константу, а `fg` и `bg` перечисляют несколько ссылок и ставят константу
последней (`See [sgr.fg256Open], ... and [sgr.FOREGROUND].`).

Тест проверен обратной мутацией: возврат `bgBlack, // 30` красит его с
точным номером строки.

**Почему это важнее самих девяти чисел.** Комментарий — единственное, что
не проверяется исполнением кода: сколько ни гоняй тесты, число в `//`
никто не прочтёт. Дрейф прожил до ревью именно поэтому.

## L21 не подтвердился

Ревью: два блока README не компилируются копипастом, «единственные два из
69». Измерение всех 72 dart-блоков:

| величина | значение |
|---|---|
| блоков всего | 72 |
| несут пакетный импорт | 15 |
| имеют `main()` | 7 |
| используют имена пакета | 62 |
| из них **без импорта** | **51** |

README сплошь написан фрагментами; «компилируется копипастом» — не тот
стандарт, которому он следует. Два помеченных блока не исключение, и
импортом они не чинятся: в первом не объявлен `logFile`, во втором `await`
стоит на верхнем уровне. Довести их до полных программ значило бы сделать
их непохожими на остальные семьдесят.

Истинное зерно нашлось меньшего размера: `stdout`, `stdin` и `FileMode` —
единственные в README имена **не из этого пакета**, и читателю неоткуда
знать, что нужен `dart:io`. Это и сказано прозой, в обоих README. Решение
владельца — закрыть пункт, а не реализовывать.

## Что померено, а не выведено

- **Вывод `Piece`** снят пробником и сличён с README построчно `diff`'ом:
  оба файла совпадают с живым выводом побайтно.
- **Восемь параметров `ansiShowEscapeSequences`** разобраны прогоном,
  меняющим по одной паре за раз. Отсюда и деталь, которую иначе пришлось бы
  угадывать: последовательность без параметров теряет не только их, но и
  оба их ограничителя.
- **Единица `lengthWithoutEscapeCodes`** — кодовые единицы UTF-16.
  Три случая расхождения с ожиданием читателя сняты пробником: эмодзи вне
  базовой плоскости даёт 2 при одном руне, разложенный акцент — 2 при одном
  видимом символе, `世界` — 2 при четырёх колонках терминала. Последнее и
  ломает вёрстку колонок молча.

## Ворота, которая не помогла, и это ожидалось

`check_readme_sync` из волны 6 **не ловит** правку L1: строки
`// Piece<Style>(...)` — комментарии внутри dart-блока, а инструмент
сравнивает позиции комментариев, но не их текст. Это ровно та остаточная
дыра, которая названа в спеке волны 6, и здесь она сработала как описано.
Дисциплина в таких правках ручная: оба README одним коммитом плюс
`diff` против живого вывода.

L21 в этом смысле безопаснее — там менялась проза вне блоков.
