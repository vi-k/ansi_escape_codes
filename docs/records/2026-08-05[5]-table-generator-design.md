## Цели и критерии готовности

Ветка `feat/table-generator` от main. Три коммита:
**маркеры → генератор → CI + pubignore**. Conventional-префиксы; версия
не трогается; слияние — локальный `merge --no-ff`, без PR.

Критерии готовности:

1. **Коммит 1 — no-op**: дифф состоит из одних комментариев-маркеров;
   `dart format`/`analyze`/`test` зелёные, поведение не тронуто.
2. **Коммит 2 — байт-в-байт**: после `dart run tool/generate.dart`
   `git diff --exit-code` пуст — генератор доказан эквивалентным
   нынешним таблицам. Это главный критерий захода.
3. **Коммит 3**: CI-шаг ловит любой дрейф (sabotage-проверка: порча
   одной строки зоны → шаг красный, откат); `dart pub publish --dry-run`
   — 0 предупреждений, `tool/` в архив не попадает.
4. Существующие тест-файлы не редактируются; M8-свип
   (`test/color_tables_test.dart`) остаётся независимой сеткой.

## Раздел 1 — архитектура

### `tool/generate.dart`

Обычный Dart-скрипт на `dart:io`, без зависимостей, в пакет не
публикуется. Внутри:

- **один источник правды** — список 256 имён таблицы в порядке индексов:
  16 именованных (`black`…`white`, `highBlack`…`highWhite`), куб
  `rgbRGB` (R,G,B ∈ 0..5, индексы 16..231), серые `gray0`…`gray23`
  (232..255). Та же грамматика, что у enum `Colors` — который сам
  генерируется из этого списка;
- **по эмиттеру на поверхность** — семь функций, каждая порождает
  строки своей зоны, включая построчные dartdoc-комментарии (их
  грамматика детерминирована по имени: «Black index from 256-color
  table.», «Foreground black from 256-color table.» и т.д. — точные
  шаблоны снимаются с фактических файлов при имплементации, критерий
  байт-в-байт не оставляет свободы);
- **замена зон на месте**: скрипт читает файл, находит пару маркеров,
  заменяет содержимое между ними, пишет обратно. Отсутствие маркера
  или непарный маркер — ошибка с именем файла и ненулевой exit code.

### Зоны и маркеры

Восемь файлов, семь поверхностей:

| Файл | Зона (генерируется) | Вне зоны (рукописное) |
|---|---|---|
| `lib/src/ansi/colors.dart` | 256 `const int` с секционными комментариями | шапка библиотеки |
| `lib/src/ready_to_use/sgr/colors256/fg256.dart` | 256 `const String fg256*` | шапка, `fg256Open`/`Close`, `fg256()` |
| `…/bg256.dart` | 256 `const String bg256*` | аналогично |
| `…/underline256.dart` | 256 `const String underline256*` | аналогично |
| `lib/src/parsing/colors/color_indexes.dart` | 256 значений enum | объявление enum, `byIndex`, операторы |
| `lib/src/parsing/colors/color_256.dart` | 256 статиков | конструкторы, `rgb`/`gray`, `==`, `id` |
| `lib/src/parsing/state/styles.dart` | 768 цветовых констант | шапка, 15 свойств |
| `lib/src/parsing/state/style_colors.dart` | 512 геттеров | шапка extension |

Маркеры — комментарии в голосе пакета, одинаковые во всех файлах
(точный текст — в плане; смысл: «generated by tool/generate.dart —
edit the generator, not this»). В зоне `underline256.dart` учесть, что
его шаблон может отличаться от fg/bg (свои Open/Close) — эмиттер
параметризуется префиксом и шаблоном значения.

### CI и упаковка

В `.github/workflows/dart.yml`, после шага analyze:

```yaml
      - name: Check the generated tables are in step with the generator
        run: |
          dart run tool/generate.dart
          git diff --exit-code -- lib/
```

`tool/` добавляется в `.pubignore` (по прецеденту
`benchmark/compare.dart`: скрипту нужен репозиторий, в архиве он
бессмыслен).

## Раздел 2 — тесты, эквивалентность, порядок коммитов

### Коммит 1 — маркеры

Расстановка пар маркеров в восьми файлах. Дифф — только комментарии.
Гейты: `dart format .` идемпотентен, полный `dart test`,
`analyze --fatal-infos`.

### Коммит 2 — генератор

`tool/generate.dart` целиком + доказательство: прогон скрипта, затем
`git diff --exit-code` (пусто) и `git status` (чисто). Если дифф не
пуст — генератор чинится до пустого диффа; **файлы таблиц под
генератор не подгоняются** (единственное исключение — если при
имплементации вскроется фактическая опечатка в таблице: тогда STOP и
отдельное решение, не молчаливая правка). Гейты те же; вдобавок
`dart run tool/generate.dart` прогоняется дважды подряд —
идемпотентность самого скрипта.

### Коммит 3 — CI + pubignore

CI-шаг как в разделе 1; `tool/` в `.pubignore`;
`dart pub publish --dry-run` — 0 предупреждений, в листинге архива нет
`tool/`. Sabotage-проверка — порча **генератора**, не зоны (порчу зоны
generate просто перезаписал бы обратно, и дифф остался бы пуст):
временно изменить в эмиттере один индекс → локальный прогон шага
(generate + `git diff --exit-code -- lib/`) красный — зона разошлась с
HEAD; откат генератора, повторный прогон зелёный, `git status` чист.
Это же показывает, что ловит CI: закоммиченную ручную правку таблицы
или генератор, изменённый без перегенерации.

### Порядок и обоснование

Маркеры первым коммитом отдельно: их дифф тривиально ревьюится как
no-op, и генератор в коммите 2 читается без шума. CI-шаг последним:
он имеет смысл только когда генератор уже в репозитории.
