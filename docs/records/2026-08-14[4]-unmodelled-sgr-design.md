# Сохранение немоделируемых SGR

> **Состояние документа**
>
> - **Тип:** спека
> - **Статус:** принята владельцем 2026-08-14, ждёт плана и реализации
> - **Актуальность:** написана против `main` @ `64ae639`
> - **Чему не верить:** точные байты новых residual-переходов ещё не
>   сняты с реализации; приведённые ниже формы задают семантику, а план
>   обязан сначала закрепить живыми пробниками исходное поведение и
>   красными тестами — требуемую дельту

## Что сломано

Все обратные выходы пакета пропускают разобранные сущности `Sgr` и
восстанавливают оформление только через `State.transitTo`. Поэтому любая
функция, которую `State` не моделирует, исчезает либо превращается в более
бедное состояние.

На живом `main` это подтверждено для трёх независимых выходов:

| вход | `optimize` / `substring` | `Printer.prepare` |
|---|---|---|
| `CSI 11 m A CSI 10 m B` | `AB` | `CSI 0 m AB` |
| `CSI 20 m A CSI 23 m B` | `AB` | `CSI 0 m AB` |
| `CSI 26 m A CSI 50 m B` | `AB` | `CSI 0 m AB` |
| `CSI 60 m A CSI 65 m B` | `AB` | `CSI 0 m AB` |
| `CSI 4:3 m A` | `CSI 4 m A` | curly становится singly |

Смешанная последовательность теряет только непокрытую часть:
`CSI 1;11;31 m` превращается в `CSI 31;1 m`. Синтаксически обычная
неизвестная функция `99` исчезает целиком, неподдержанная форма цвета
исчезает рядом с известными функциями, а чрезмерно большое число идёт по
другой ветке: `int.parse` роняет разбор до `CsiUnknown`, и вся
последовательность копируется дословно.

Это не только потеря байтов. Простое сохранение `CSI 11 m` без знания о
последующем `CSI 10 m` оставит альтернативный шрифт активным, если
оптимизатор удалит второй код как немоделируемый. Аналогично `CSI 4:3 m`
нельзя записать рядом с синтетическим `CSI 4 m`: поздний код изменит curly
на обычное подчёркивание. Для среза, новой строки принтера, вставки и
возврата курсора состояние приходится ещё и восстанавливать через
границу, на которой исходного открытия уже нет.

## Принятый контракт

Известные стандартные функции становятся полноценной публичной частью
`State`, `Style` и `Stack`. Всё, чему пакет не может приписать достоверную
семантику, переносится отдельным приватным residual-каналом рядом со
`State` и каналом гиперссылки.

Контракт относится ко всем обратным поверхностям: `optimize`,
`substring`, вставкам, `Printer`/`StackedPrinter`, их sink-вариантам и
сохранению/восстановлению состояния через `ESC 7`/`ESC 8`.

Цель — сохранить наблюдаемую терминальную семантику, а не исходную
группировку известных параметров по SGR. Известные функции по-прежнему
можно канонизировать и объединять до первого неизвестного параметра.
Неизвестный параметр сохраняется без догадки о его эффекте.

`SGR 0` остаётся общим барьером SGR-состояния: он сбрасывает и публичную
модель, и residual, но не закрывает hyperlink. Принятое разделение
ссылочного канала и `State` не меняется.

## Публичная модель

### Альтернативные шрифты

Новый публичный enum:

```dart
enum FontSelection {
  primary,
  alternative1,
  alternative2,
  alternative3,
  alternative4,
  alternative5,
  alternative6,
  alternative7,
  alternative8,
  alternative9,
}
```

Коды `10–19` становятся известными парсеру. `State` получает
`fontSelection`, fluent-переходы к девяти альтернативам и `resetFont` для
возврата к primary. `Style` хранит primary как терминальное значение по
умолчанию; `Stack` хранит историю выбора в persistent frame и трактует
`resetFont` по своему существующему стековому контракту — снимает верхний
уровень. Исправление общей reset-семантики `Stack` относится к H7 и в эту
волну не входит.

### Italic и fraktur

Новый публичный enum:

```dart
enum FontShape { italic, fraktur }
```

`FontShape? fontShape` равен `null` для обычного начертания. Существующие
`isItalic`, `italic` и `resetItalic` сохраняются. Добавляются `isFraktur`,
`fraktur` и точное общее имя `resetFontShape`. Код `23` снимает обе формы;
`resetItalic` остаётся совместимым именем той же операции и получает
явный дартдок об общем сбросе. В `Style` параметры `italic` и `fraktur`
взаимоисключающие, а `Stack` ведёт их одной историей, потому что один SGR
сбрасывает обе.

### Расширенные подчёркивания

Существующий `UnderlineStyle` расширяется без переименования старых
значений:

```dart
enum UnderlineStyle { singly, doubly, curly, dotted, dashed }
```

Разбор двоеточечной формы точный:

| параметр | состояние |
|---|---|
| `4:0` | underline отсутствует |
| `4:1` | `singly` |
| `4:2` | `doubly` |
| `4:3` | `curly` |
| `4:4` | `dotted` |
| `4:5` | `dashed` |
| прочий `4:n` | residual |

Добавляются `curlyUnderline`, `dottedUnderline` и `dashedUnderline`.
Существующие `underline`, `doublyUnderline`, `isUnderline`,
`isDoublyUnderline` и `resetUnderline` остаются. `isUnderline` продолжает
означать одинарное семейство и истинен для singly, curly, dotted и dashed;
`isDoublyUnderline` истинен только для doubly.

### Proportional spacing и ideogram

Коды `26/50` становятся публичным булевым свойством
`isProportionalSpacing` с переходами `proportionalSpacing` и
`resetProportionalSpacing`.

Для `60–65` вводится:

```dart
enum IdeogramStyle {
  underline,
  doublyUnderline,
  overline,
  doublyOverline,
  stress,
}
```

`IdeogramStyle? ideogramStyle` равен `null` после `65`. Для пяти значений
добавляются `ideogramUnderline`, `ideogramDoublyUnderline`,
`ideogramOverline`, `ideogramDoublyOverline`, `ideogramStress` и общий
`resetIdeogram`.

### Поверхность `Style` и совместимость

Константный конструктор `Style` сохраняет существующие bool-параметры и
добавляет:

- `FontSelection fontSelection = FontSelection.primary`;
- `bool fraktur = false`, взаимоисключающий с `italic`;
- `bool curlyUnderline`, `bool dottedUnderline` и `bool dashedUnderline`,
  взаимоисключающие со старыми `underline` и `doublyUnderline`;
- `bool proportionalSpacing = false`;
- `IdeogramStyle? ideogramStyle`.

`Styles` получает константы для новых устанавливаемых свойств. Готовый
SGR-слой получает симметричные строки установки и сброса, включая
`primaryFont`, девять альтернатив, fraktur, proportional spacing,
ideogram и три новых подчёркивания. Сырые числовые константы и таблицы
меняются через генератор там, где их зоны сгенерированы.

Ни одно существующее публичное имя не удаляется и не переименовывается.
В частности, элементы `ControlFunctionsSGR` с историческими именами
`reserved_26`, `reserved_50`, `reserved_60`–`reserved_65` остаются
элементами enum; меняются их документация, признак поддержанности и
семантическая обработка. Публичные удобные имена живут в state- и
ready-to-use-слоях, поэтому исправление не требует ломать `.name`,
`values` и exhaustive switch пользователей.

Все новые свойства входят в `State.transitTo`, `changeDefaultsTo`,
равенство, `hashCode`, `toString` и преобразование `Stack` в видимый
`Style`. Равенство `Stack`, как и сейчас, сравнивает видимое состояние, а
не историю его получения.

## Приватный residual-канал

Residual не входит в `State` и его равенство. Приватный снимок передаётся
рядом с `{state, link}` и содержит:

- видимый базовый `Style` непосредственно перед первым неизвестным
  параметром;
- хвост неизменяемой цепочки эмиссий;
- корень, предыдущий узел и глубину для определения продолжения и
  расхождения ветвей без копирования истории.

Узел хранит готовую завершённую SGR-эмиссию. Неизвестный параметр из
смешанной последовательности оборачивается в самостоятельный
`CSI <raw-parameter> m`; overflowed SGR, который невозможно разложить,
хранится целиком.

После открытия residual каждый последующий распознанный SGR-параметр до
настоящего `0` тоже обязан попасть в журнал, даже если публичный `State`
от него не изменился. Неизвестная функция могла сама изменить то же
свойство, поэтому «избыточный» известный setter после неё нельзя удалять.

Для `Style` такой параметр записывается своей канонической операцией. Для
`Stack` reset сначала выполняет входную операцию, затем при необходимости
добавляет восстановление видимого значения нижнего frame. Например,
снятие верхнего bold при оставшемся нижнем bold требует `22;1`, даже если
видимый `Stack` до и после равен bold. Это сериализация операции, а не
только разницы двух поверхностей.

Пока residual активен, синтетический переход не имеет права выбирать
полный `SGR 0` как сокращение: он стёр бы неизвестное состояние. Полный
reset появляется только когда `0` действительно был во входе либо когда
выход сознательно покидает непрозрачную ветвь и должен её очистить. Все
остальные сбросы внутри журнала селективны.

### Переход между снимками

Эмиттер различает четыре случая:

1. Оба residual отсутствуют — работает существующий `State.transitTo`.
2. Целевой хвост продолжает текущий — пишется только добавившийся суффикс.
3. Текущий residual отсутствует, целевой есть — известное состояние
   переводится к базовому `Style`, затем журнал переигрывается с корня.
4. Текущий residual активен, а цель отсутствует либо лежит на другой
   ветви — пишется `SGR 0`, затем целевой базовый стиль и журнал, если они
   есть.

Пример состояния после `CSI 31 m`, `CSI 99 m`, `CSI 1 m`: базовый стиль
red и журнал `99 → bold`. Если `substring` начинается после этих кодов,
он устанавливает red, переигрывает raw `99`, затем bold. Если следующий
снимок — прямое продолжение, повторяются только новые узлы.

Отдельная функция `SGR 0` внутри параметрического списка немедленно
отбрасывает предыдущую ветвь; пустой параметр, который существующий
парсер нормализует в `0`, имеет тот же смысл. Ноль внутри аргументов
цвета или иной составной функции барьером не является. Параметры после
reset обрабатываются с чистой моделью; неизвестный параметр после него
открывает новый root. Если неизвестный стоял до reset, а текста между
параметрами быть не могло, его журнал не обязан выходить.

## Разбор и граница SGR

Функции внутри обычного SGR обрабатываются строго слева направо. До
первого неизвестного параметра известные изменения сворачиваются в
публичный `State`. Неизвестный параметр открывает residual после уже
применённых известных функций, а все следующие функции идут через его
операционный журнал до `0`.

К stateful SGR относятся `CSI` с параметрами только из цифр, `;` и `:`,
заканчивающиеся `m`. Если такая оболочка стала `CsiUnknown` только из-за
числового переполнения или невозможности разобрать её параметр, она
попадает в residual целиком. Даже если внутри её байтов виден `0`,
частично разобрать такую последовательность и признать его reset нельзя;
непрозрачное состояние живёт до следующего отдельно и успешно
разобранного `SGR 0`.

Не входят в residual:

- private CSI вроде `CSI ? ... m`;
- CSI с промежуточными байтами;
- неизвестные CSI с другим финальным байтом;
- незавершённые escape-последовательности.

Они продолжают проходить в выход буквально и не считаются состоянием,
которое надо переиграть в более позднем срезе. Неподдержанные формы цвета
внутри обычной SGR-оболочки, напротив, являются residual: они меняют
графическое оформление, хотя пакет не знает как именно.

Ни один из этих случаев не создаёт нового исключения. Малые неизвестные,
неподдержанные двоеточечные формы и overflow получают единый принцип:
не угадывать и не терять.

## Прохождение через операции

Приватный снимок добавляется к `Piece`, итоговому результату разбора и
начальному контексту итератора без изменения публичной поверхности этих
типов.

- `substring` использует residual первого включённого текста и может
  восстановить состояние, открытое до начала среза.
- Вставка разбирается из ambient-тройки `{state, link, residual}`. После
  ветки вставленного текста исходная ветвь восстанавливается общим
  переходом; `insertAfter` на границе незавершённой последовательности и
  безопасное переиздание вставки остаются отдельным неизменным слоем.
- `Printer` и `SinkPrinter` переносят residual между строками вместе с
  последним state и ambient-link. После принудительного reset новой
  строки базовый стиль и журнал открываются заново.
- `ESC 7` сохраняет, а `ESC 8` восстанавливает всю логическую тройку.
  Последующие изменения образуют ветвь; переход назад делает reset и
  переигрывает сохранённый target.
- `StackedParser` и stacked-принтеры используют тот же residual, но
  строят известные операции по стековой семантике reset.

Канал hyperlink остаётся независим: дополнительные SGR-reset и replay
не закрывают OSC 8 и не меняют его terminator или `id=`.

## Стоимость

Пока неизвестного SGR нет, residual равен `null`, узлы журнала не
создаются, а обратные выходы идут по прежнему быстрому пути. Новые
стандартные функции покрывает публичный `State`, поэтому обычные alternative
font, fraktur, proportional spacing, ideogram и расширенный underline сами
по себе журнал не открывают.

После неизвестной функции создаётся один persistent-узел на сохраняемую
операцию. Строка накопленной истории не конкатенируется; прямое
продолжение выдаётся за время, пропорциональное новому суффиксу. Полный
replay требуется только при входе в ветвь или расхождении. Настоящий
`SGR 0` отпускает активную ссылку на историю; старые узлы живут лишь пока
их держат уже построенные pieces или сохранённая ветвь.

Если неизвестное состояние не сбрасывается через много строк, журнал
неизбежно растёт, а принтер после собственного reset должен переигрывать
его на каждой строке. Сократить неизвестную историю без знания её
семантики нельзя. Это принимаемая цена выбранного полного контракта, но
существующий `memory_guard` не перекалибровывается без отдельного решения
владельца.

## Проверки

### Публичное состояние

1. Каждый новый код устанавливает и сбрасывает ожидаемое значение в
   `Style` и `Stack`.
2. Конструктор `Style`, fluent-переходы, `Styles`, equality, hash,
   `toString`, `changeDefaultsTo` и `transitTo` покрыты отдельно.
3. Совместно сбрасываемые семьи проверяют reapply выжившего значения:
   italic/fraktur, пять underline и пять ideogram.
4. Вложенный `Stack` проверяет pop верхнего frame без попытки решить H7
   для остальных свойств.

### Разбор

1. Одиночные и смешанные `10–20`, `26/50`, `60–65`.
2. Точные `4:0`–`4:5` и residual для прочего `4:n`.
3. Неизвестный параметр до и после известного setter, включая setter,
   который выглядит избыточным в публичной модели.
4. Неподдержанный цвет, малый unknown и overflowed SGR.
5. `0` перед unknown, после unknown и между ними в одной
   параметрической последовательности.
6. Private/intermediate/non-SGR CSI остаются literal и не replay.

### Обратные поверхности и ветви

1. Матрица `optimize`, `substring`, обе вставки, print/sink и stacked
   вариантов.
2. Начало среза внутри residual, последовательный суффикс, уход в чистое
   состояние и расхождение двух ветвей.
3. Reset внутри вставки с восстановлением внешнего unknown и unknown
   внутри вставки с восстановлением чистого ambient.
4. Продолжение через несколько строк и полное открытие после reset
   принтера.
5. `ESC 7/8` сохраняет и восстанавливает residual вместе с hyperlink и
   `State`.
6. Двойной `optimize` стабилен.

Регрессионная матрица обязательно сохраняет H4: `insertAfter` на границе
незавершённой последовательности, четыре формы незавершённого кода во
вставке и plain-инвариант обратной сборки. Отдельный тест подтверждает,
что `SGR 0` не закрывает hyperlink.

Ожидаемые байты существующего поведения перед планом снимаются пробником
с живого кода. Новая семантика сначала записывается красными тестами;
если фактический вывод расходится с ожиданием, причина объясняется по
операционному журналу, а ожидание не подгоняется под реализацию.

Финал проходит все ворота из `AGENTS.md`, включая генератор,
`check_entry_points`, полный `dart test`, `memory_guard`, dartdoc и
publish dry-run.

## Отклонённые варианты

### Только сырой transcript для всех непокрытых функций

Он сохранял бы семантику, но оставлял стандартные alternative fonts,
fraktur, proportional spacing, ideogram и extended underline невидимыми
для публичных `State`, `Style` и `Stack`. Пользователь выбрал публичную
модель для известных свойств; transcript остаётся только страховкой для
действительно неизвестного.

### Arena и числовые индексы

Общий изменяемый arena уменьшил бы размер снимка, но добавил бы владение,
жизненный цикл и риск удержания всех ветвей принтерами. Persistent-цепь
уже даёт структурное разделение, естественную проверку ancestry и
освобождение после reset без отдельного сборщика.

### Расширять публичную модель для каждого встреченного числа

Для `99`, vendor extension, неизвестного цвета или overflow невозможно
назвать корректное свойство и правило сброса. Публичный мешок сырых кодов
перенёс бы внутреннюю проблему в API и всё равно не решил бы порядок.
Residual сознательно остаётся приватным.

## Не входит в волну

- изменение reset-контракта `Stack` из H7;
- исправление `substring(close: false)` из H5;
- моделирование private или intermediate CSI как SGR;
- гарантия байт-в-байт для канонизируемых известных функций;
- новый публичный доступ к residual;
- смена SDK-floor, версии, тег или публикация;
- отдельная оптимизация скорости `substring`, потолок которой уже
  измерен и закрыт предыдущей волной.
