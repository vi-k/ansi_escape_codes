# Спека — `Match` уходит, приходит `Piece`

> **Состояние документа**
>
> - **Тип:** спека волны H9, 2026-08-13
> - **Статус:** согласована с владельцем, план и реализация впереди
> - **Актуальность:** пишется на `main` @ `ad075bf`; числа поверхности
>   сняты с этого коммита пробником и `grep`, не по памяти
> - **Чему не верить:** ничему заранее — документ новый; если он разойдётся
>   с репозиторием, прав репозиторий

## Что чиним

`H9` из отчёта `docs/records/2026-08-13[5]`: публичный `Match<S>` молча
перекрывает `dart:core.Match`. Молча — потому что **явный импорт старше
неявного `dart:core`**, поэтому неоднозначности, о которой говорит
README, не возникает: имя пакета просто побеждает, и обычный Dart-код с
регулярками падает двумя ошибками, ни одна из которых не называет пакет.

```dart
import 'package:ansi_escape_codes/ansi_escape_codes.dart';
for (final Match m in RegExp(r'\w+').allMatches('a b')) { print(m.group(0)); }
```

```
error - The type 'Iterable<RegExpMatch>' ... can be assigned to 'Match<State<dynamic>>'
error - The method 'group' isn't defined for the type 'Match'
```

Пять остальных имён из того же README-абзаца (`Text`, `State`, `Stack`,
`Colors`, `Color`) — флаттерные, и про них README прав: Flutter
импортируют явно, две явных стороны дают неоднозначность, и компилятор
действительно спрашивает, что имелось в виду. Ложна фраза только из-за
`Match`, стоящего в том же списке.

**4.0.0 не издана — это последний бесплатный момент.** `Match` был
публичен и в изданной 3.1.2 (`lib/src/parsing/parser/matches/match.dart`
в дереве тега `v3.1.2`), так что переименование ломающее в любом случае;
но 4.0.0 и так несёт списки Renamed и Removed, а после публикации цена
вырастет на порядок.

## Решения владельца

1. **`Match<S>` → `Piece<S>`.** Слово, которым пакет уже говорит об этой
   вещи: дартдок самого класса открывается словами «One piece of a parsed
   string», а внутри живут `_pieceAt`, `nextPiece`, `takePiece` — слово
   `piece` встречается в `lib/` 65 раз. Переименование не вводит термин, а
   узаконивает свой. Ни `dart:core`, ни Flutter имени `Piece` не занимают.
2. **`Matches<S>` → `Pieces<S>`, геттер `Parser.matches` →
   `Parser.pieces`.** Слово «match» уходит из публичного API целиком,
   вместо того чтобы остаться в половине имён.
3. **Переименование ведётся до конца:** приватные имена, имена файлов и
   папка — тоже. Иначе внутри останутся два слова об одной вещи, и
   следующая волна будет читать оба.

## Объём

### Переименовывается

| было | стало |
|---|---|
| `Match<S>` | `Piece<S>` |
| `Matches<S>` | `Pieces<S>` |
| `Parser.matches` (геттер) | `Parser.pieces` |
| `_MatchesResult<S>` | `_PiecesResult<S>` |
| поле `_MatchesResult.matches` | `_PiecesResult.pieces` |
| папка `lib/src/parsing/parser/matches/` | `.../pieces/` |
| `matches/match.dart` | `pieces/piece.dart` |
| `matches/matches.dart` | `pieces/pieces.dart` |
| `matches/matches_result.dart` | `pieces/pieces_result.dart` |
| `matches/parser_iterator.dart` | `pieces/parser_iterator.dart` (имя то же, переезжает) |

Файлы переносятся `git mv`, чтобы `git log --follow` по ним остался
прямым.

### **Не** переименовывается

**`_MatchingState`** (`lib/src/parsing/parser/entities/matching_state.dart`)
— и это главное исключение спеки. Он держит `RegExpMatch` движка
регулярок:

```dart
final class _MatchingState<S extends State<S>> {
  final RegExpMatch match;
  S state;
```

Его «match» — совпадение регулярного выражения, а не кусок разобранной
строки; он и лежит в `entities/`, а не в `matches/`. Сплошная замена
слова по репозиторию испортила бы верное имя. Заодно остаются нетронутыми
`RegExpMatch`, `namedGroup` и всё, что через них читается.

`_ParserIterator` имени не меняет — в нём нет спорного слова; меняется
только тип, который он выдаёт (`Iterator<Piece<S>>`), и путь файла.

### Документация — тем же коммитом

- **`README.md` и `README.ru.md`** (по 16 упоминаний). Из списка
  перекрывающихся имён уходит `Match`; остаются пять флаттерных, и
  фраза про вопрос компилятора становится верной, потому что относится
  теперь только к ним. Правило репозитория: английский — источник,
  перевод правится **тем же коммитом**, расхождение считается дефектом.
- **`CHANGELOG.md`** — запись в Renamed. Версия не бампается, 4.0.0
  правится на месте.
- **`docs/architecture.md`** — 5 упоминаний.
- **`example/`** (1 файл) и **`benchmark/`** (2 файла).

### Тесты

- 92 обращения к `.matches` в `test/` — механическая замена; названия
  тестов, где «match» стоит как слово прозы, правятся по смыслу.
- **Новый страж имени.** Тест-файл, который импортирует пакет одним
  импортом — так, как это делает пользователь, — и рядом пользуется
  `dart:core.Match` через `RegExp.allMatches`, читая `group`. Пока имя
  свободно, файл компилируется; вернуть `Match` в публичный экспорт — и
  он краснеет. Такого стража у пакета не было, и это причина, по которой
  находка дожила до ревью: имя проверялось изнутри пакета, где `Match`
  всегда значил свой, а не снаружи, где он значит чужой.

**Deprecated-алиаса не будет.** `typedef Match<S> = Piece<S>` в публичном
экспорте воспроизвёл бы ровно ту коллизию, ради которой всё затевается:
имя снова перекрыло бы `dart:core` молча. Ломающее переименование без
моста — сознательный выбор, и он записан в CHANGELOG.

## Как проверяется, что сделано

1. **Ворота целиком** (`AGENTS.md`): формат, `analyze --fatal-infos`,
   `check_entry_points.dart`, `generate.dart` без диффа, `dart test`,
   `memory_guard.dart`, `dart doc --dry-run`, `pub publish --dry-run`.
2. **`grep` по `\bMatch\b`** в `lib/`, `test/`, `example/`, `benchmark/`
   оставляет только `RegExpMatch`, `_MatchingState` и то, что через них
   читается. Всё прочее — ошибка переноса.
3. **Страж проверяется мутацией**: временный
   `typedef Match<S> = Piece<S>` в публичном входе роняет новый тест.
   Правило репозитория: тест, который не видели красным, — не тест.
4. **Ожидаемые значения снимаются пробником с живого кода.** За прошлую
   волну это правило сработало шесть раз, и все шесть раз неправ был не
   код. Здесь пробником проверяются: число мест до правки, компиляция
   стража до и после, отсутствие `Match` в выводе `dart doc`.

## Чем это не является

- Не трогает пять флаттерных имён: у них отказ громкий, и README про них
  говорит правду. Отдельного решения владельца на них не было.
- Не меняет поведение: ни одна строка не разбирается и не собирается
  иначе. Прежние 809 тестов должны остаться зелёными **без единой правки
  ожидания** — правка ожидания здесь была бы признаком ошибки переноса, а
  не следствием переименования. Прибавится к ним только страж имени.
- Не заводит `Piece` как новую сущность: это то же самое, что было
  `Match`, с теми же пятью полями.

## Риски

- **Механическая замена по слову.** Слово «match» в пакете стоит в двух
  смыслах, и один из них верный. Отсюда исключение `_MatchingState`,
  записанное выше, и проверка `grep`-ом в конце.
- **`part`-директивы.** Файлы переезжают, и `parser.dart` перечисляет их
  явно; ошибка здесь роняет компиляцию, то есть ловится первой же
  командой ворот.
- **Проза документации.** В README и `architecture.md` слово стоит не
  только в коде примеров, но и в тексте; замена вслепую даст фразы вроде
  «кусок разобранной строки — это piece» там, где по-русски написано
  иначе. Правится чтением, а не `sed`-ом.
