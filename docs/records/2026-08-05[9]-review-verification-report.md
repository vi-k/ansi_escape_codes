# Разбор незакрытых пунктов

## M5 (пункт 9): фикс работает, но перекрыт регрессией из того же PR

Заявленные механизмы существуют и дают эффект: ленивый `Text` на офсетах,
`_MatchesResult` без копии списка. Их суммарный вклад против baseline —
скромные −27 МБ (плотный вход) / −15 МБ (смешанный).

Но бисект по RSS (10 МБ плотного входа, 3,08 млн матчей) указал на коммит
`1c53a02` того же PR #10: **+303 МБ** одним шагом. Виновник —
`sgr.dart:26-27`: замена `List.unmodifiable` (компактная копия) на
`UnmodifiableListView` (view, удерживающий growable-список вместе с
запасом ёмкости backing-массива): 127 байт/список против 52–67.

Прямое доказательство — откат ровно этих двух строк на копии HEAD:

| Вход 10 МБ | baseline | HEAD | HEAD − 2 строки |
|---|---|---|---|
| плотный | 661 МБ | **966 МБ** | 634 МБ |
| смешанный (лог) | 188 МБ | **244 МБ** | 173 МБ |

Подтверждено и живой кучей (`--old_gen_heap_size`): baseline проходит при
700 МБ, HEAD требует ~1000 МБ — +43 % удерживаемой памяти, не шум RSS.
По времени откат бесплатен на больших входах (~9 % только на 100 кБ
плотного). Итог: удержание выросло с ~66× до ~96× размера входа —
находка ревью не закрыта, а усилена в ~1,46×.

CHANGELOG подаёт эту замену как экономию («wrapped once rather than
copied twice») — формулировка не соответствует измеренному эффекту.

**Рецепт:** вернуть `List.unmodifiable` в `sgr.dart:26-27` (2 строки),
поправить абзац CHANGELOG, добавить сторожевой замер удержания в
бенчмарк/тесты (сейчас строка `rss delta` в бенчмарке есть, но корпус мал
и её никто не сверяет).

## M7 (пункт 14): механизмы внесены, эффект нулевой

Байтовая диспетчеризация (`entity.dart:89-96`) и кэш
`SgrSimpleFunction._of` (`sgr.dart:434-438`) существуют. Но на плотном
входе 10 МБ HEAD **на ~1,5 % медленнее** baseline (1871 против 1843 мс);
выигрыш ~10 % на 100 кБ почти целиком принадлежит сканеру H3, а не M7.
Цель ревью была 1,5–2×.

Причины: `namedGroup` не кэширован (`matching_state.dart:9` — геттер), и
байт-диспетчеризация даже **добавила** один вызов `namedGroup` на
CSI/SGR-путь (5 против 4 у baseline) — а плотный вход это сплошной SGR;
`split(';')`/`split(':')` на месте. Остаточная стоимость ~40 % времени
на матч — почти как названные ревью ~50 %. CHANGELOG честно признаёт
(«measures at noise level»), то есть пункт закрывался по факту «сделаны
механизмы», а не «получен эффект».

**Рецепт минимум:** `late final String string = match.namedGroup('all')!`
полем вместо геттера (снимает и внесённый лишний вызов); дальше — по
желанию, пункт может быть честно переведён в «принятое ограничение».

## L7 (пункт 11, частично): та же дыра в extensions.dart

`lib/extensions.dart` не экспортирует `ControlFunctionsC0`, при этом
публичная сигнатура `ansiRemoveControlCodes({Set<ControlFunctionsC0>
exclude})` (`remove.dart:50-51`) видна из этой точки. Пользователь
`extensions.dart` не может назвать тип аргумента — ровно класс дрейфа L7,
причём API новый в 4.0.0, уедет в первый же релиз. Фикс — одна строка
экспорта + строка в `entry_point_extensions_test.dart`. Смежно: тесты
`entry_point_*` — рукописные перечисления, а не вычисление замыкания;
формулировка CHANGELOG «every entry point carries a closure test»
завышена.

# Рекомендация перед публикацией 4.0.0

3. **`late final` поле вместо геттера `string`** в `matching_state.dart`

либо перевод в принятое ограничение с текущей честной формулировкой

# Методика (для воспроизводимости)

Пять параллельных верификаторов, каждый — только код/тесты/git + пробы:

- **Корректность**: фейк-Stdin с windows-правилами, симуляция отката;
  фаззинг вставок/срезов с суррогатами (seed 20260805), 30 137 проб.
- **SGR**: 13 225 исчерпывающих пар + ~220 тыс. композиций + ~1,5 млн
  случайных CSI побайтовым генератором; оракул сильнее репозиторного —
  пофункциональная сохранность списков `SgrFunction`.
- **Производительность**: A/B против `perf-baseline-4.0.0` (`b9494a9`)
  через `git archive` 12 ревизий; бисект RSS; проверка живой кучи
  `--old_gen_heap_size`; 141 060 + 61 305 дифференциальных сверок
  fast-path и кэша разбора.
- **API/состояние**: механическое вычисление замыкания всех 5 точек
  входа по 80 публичным именам; пробы компиляции.
- **Инфраструктура**: мутационное тестирование табличных тестов
  (12 инъекций) и CI-шага generate+diff в изолированной копии; сверка
  SHA-пинов с тегами через GitHub API.
