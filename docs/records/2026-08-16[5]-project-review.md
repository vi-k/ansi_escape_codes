# Project overview

Dart-пакет для разбора и печати строк с ANSI-escape-кодами. 20 078 строк в
`lib/` (значительная часть — дартдок и генерируемые таблицы), 71 файл тестов,
одна рантайм-зависимость (`meta`).

**Пять публичных входов**, 1648 экспортируемых имён:

| вход | что даёт |
|---|---|
| `ansi_escape_codes.dart` | зонтичный: всё, кроме сырых байтовых таблиц |
| `ansi.dart` | константы стандарта (C0, C1, CSI, SGR, цвета, ESC Fs) |
| `extensions.dart` | те же операции методами `String` |
| `style.dart` | модель состояния и парсер |
| `utils.dart` | `tabs`, `currentCursorPos` |

**Конвейер разбора.** Вход режет пара «сканер + регулярка»:
`_ParserIterator._read` идёт байтовым `indexOf('\x1B')` и только на найденном
`ESC` прикладывает `escapeCodesRe` через `matchAsPrefix`. Каждый кусок
становится `Piece<S>` — сущность, состояние после неё и действующая ссылка.
Сущности — sealed-модель `Entity`: `Text`, `Csi`, `Esc`, `Sgr`,
`ControlString` (`Osc`, `Dcs`, `Sos`, `Pm`, `Apc`). Нераспознанное сохраняется
исходными байтами, поэтому разбор и обратная сборка дают строку байт в байт.

**Четыре канала переноса** идут рядом, а не внутри состояния: `State`
(`Style` — значение, `Stack` — история), ссылка (`Link`), непрозрачный
SGR-residual и слот `ESC 7`/`ESC 8`.

**Ленивость и курсор.** `Pieces` отдаёт итератор, складывающий прочитанное в
кэш `_PiecesResult`. Позиционные вопросы идут не по кэшу, а по резюмируемому
курсору `_Walk`: вопрос вперёд продолжает с места остановки, вопрос назад
начинает обход заново.

**Печать** — две пары: `Printer`/`StackedPrinter` получают строку целиком,
`SinkPrinter`/`StackedSinkPrinter` — по куску за раз.

Ядро ценности — `State.transitTo`: коды перехода из состояния в состояние, а
не «сброс и всё заново». Из него растут `optimize`, переоткрытие стиля в
срезе и печать.

# Critical and high-severity findings

## C1 — Critical. `currentCursorPos(stdout, stdin)` ломает терминал и всегда падает

**Файлы:** `lib/src/utils/current_cursor_pos.dart:36-68` (внешний `try/finally`),
`:134-140` (`finally { await subscription.cancel(); }`),
`:63-68` (`on Object catch (_)`).

**Проблема.** Порядок разрушения обратен порядку создания:

```
stdin.echoMode = false; stdin.lineMode = false;
  _readReport(...)  →  finally { await subscription.cancel(); }   // ① закрывает fd 0
finally { restore lineMode; restore echoMode; }                   // ② падает
on Object catch (_) → UnsupportedError('Device Status Report not supported')  // ③ прячет причину
```

Отмена подписки на настоящий `Stdin` закрывает дескриптор. Внешний `finally`
выполняется уже после этого и падает `StdinException: Bad file descriptor,
errno = 9`. Это исключение ловит `on Object catch (_)` и подменяет его на
`UnsupportedError('Device Status Report not supported')` — то есть корректный
ответ терминала выбрасывается, а пользователю сообщается, что терминал DSR не
поддерживает.

**Сценарий (воспроизведено под настоящим pty; родитель отвечает на `CSI 6 n`
корректным `CSI 12;34 R`):**

```
parent: at start   ECHO=True  ICANON=True
parent: saw DSR    ECHO=False ICANON=False
parent: settled    ECHO=False ICANON=False     ← режимы не вернулись
--- лог ребёнка ---
THREW : Unsupported operation: Device Status Report not supported
after : THREW StdinException: Error getting terminal echo mode,
        OS Error: Bad file descriptor, errno = 9
```

Контроль — тот же pty, тот же ответ, отличается один аргумент:

```
currentCursorPos(stdout, stdin, input: stdin.asBroadcastStream())
parent: after ans  ECHO=True ICANON=True
RESULT: (12, 34)
```

**Последствия.** Пользователь остаётся в shell без echo и без канонического
режима: ввод невидим, `Ctrl-C` и построчное редактирование не работают.
Лечится только `stty sane`. Функция при этом всегда сообщает, что терминал
не умеет DSR. Затронуты `README.md:1398` и поставляемый
`example/control.dart:146` — то есть ровно то, что пользователь скопирует.

**Почему это пережило 915 тестов и CI.** `test/current_cursor_pos_test.dart`
подставляет `_FakeStdin` поверх обычного `Stream`, у которого `cancel()`
ничего не закрывает: оракул проверяет то, чего в настоящем `Stdin` нет. CI
гоняет `example/control.dart` с `< /dev/null` (`.github/workflows/dart.yml:92-100`),
где `stdin.hasTerminal` ложно и код выходит до этого места. Обе проверки
зелёные, обе мимо.

**Направление.** Восстанавливать режимы **до** отмены подписки: владение
подпиской вынести в `currentCursorPos`, порядок — restore, затем `cancel()`.
Либо для `input == null` не звать `cancel()` вовсе. Заодно сузить
`on Object catch (_)` до ожидаемых типов: он прячет не только этот дефект.

**Confidence: high** (воспроизведено под pty на macOS/Dart 3.13; для
Windows-ветки — medium, механизм тот же, не проверялся).

## H1 — High. `SinkPrinter` разрушает последовательность, разрезанную между `write`

**Файлы:** `lib/src/parsing/parser/printer.dart:359` (`final buf = StringBuffer(reset);`
— безусловный ведущий reset в `_prepare`), `:664-687` (`_writeBuf`/`_writeLine`),
`:620-655` (`write`, `writeAll`, `writeCharCode`).

**Проблема.** Каждый `write` обрабатывается как самостоятельный кусок и
**всегда** начинается с `CSI 0 m`. Если предыдущий `write` кончился посреди
последовательности, её хвост уже ушёл в sink, а между половинами вклинивается
reset. Вторая половина становится видимым текстом.

**Сценарий (воспроизведено):** вход `\x1B[31mred\x1B[0m`

```
целиком   : <ESC>[0m<ESC>[31mred<ESC>[0m           видно "red"        (красный)
по байту  : (через публичный writeCharCode)        видно "[31mred[0m" (цвет потерян)
разрез @1 : <ESC>[0m<ESC><ESC>[0m[31mred           видно "[31mred"
разрез @2 : <ESC>[0m<ESC>[<ESC>[0m31mred           видно "31mred"
разрез @3 : <ESC>[0m<ESC>[<ESC>\3<ESC>[0m1mred     видно "31mred"
```

Гиперссылка ломается тем же механизмом: `"click tail"` →
`"]8;;https://x\click]8;;\ tail"`.

**Тот же механизм убивает суррогатную пару** (`'a😀b'`, разрез между
половинами):

```
целиком : утф-8 [27,91,48,109, 97, 240,159,152,128, 98]
разрез  : утф-8 [27,91,48,109, 97, 239,191,189, 27,91,48,109, 239,191,189, 98]
                                   └─ U+FFFD ─┘              └─ U+FFFD ─┘
```

Эмодзи уничтожен необратимо. Внутренняя сверка пакета этого не видит:
`ansiRemoveEscapeCodes` склеивает половины через код, поэтому тест,
сравнивающий «видимый текст», расхождения не находит.

**Почему это дефект, а не документированное ограничение.** Пакет обещает
обратное в трёх местах:

- дартдок `SinkPrinter` (`printer.dart:69-90`): «It continuous tracks the
  current [Style] across multiple write operations»; «a link may be composed
  of several of them»; «The terminator an unterminated control string owes is
  paid in the same place»;
- README `:639`: «keep the style across the writes»;
- `docs/architecture.md:112-114`: «`SinkPrinter` и `StackedSinkPrinter` — по
  куску за раз».

Нигде не сказано, что последовательность должна целиком поместиться в один
`write`. При этом `writeCharCode` — публичный метод, делающий нарушение
тривиальным, а поток из `Process.stdout.transform(utf8.decoder)` режется где
попало по построению.

`Printer`/`StackedPrinter` **не затронуты**: они копят строку в `_lineBuf` и
отдают в `prepare` целиком (`printer.dart:508-534`). Разрез по границам целых
последовательностей тоже чист — 26 784 разбиения без расхождений.

**Направление.** Механика уже есть внутри `_prepare` (`heldOpening` +
`_terminatedOpening`), ей не хватает переноса между вызовами: завести у
`_SinkPrinterBase` carry-поле рядом с `_writtenLink`/`_owesTerminator` —
незавершённый хвост куска не писать в sink, а приклеить в начало следующего
`write`. Одиночный высокий суррогат придержать так же.
`_SinkPrinterBase.prepare` (`printer.dart:603-619`) должен откатывать и его.

**Confidence: high** (воспроизведено на публичном API).

## H2 — High. `Link` молча затеняет `dart:io.Link`

**Файл:** `lib/src/parsing/parser/entities/osc.dart:168`, экспортируется из
`lib/ansi_escape_codes.dart` и `lib/style.dart`.

**Проблема.** Пересечение export-namespace всех пяти входов с `dart:core`,
`dart:io`, `dart:async`, `dart:convert`, `dart:math`, `dart:collection` даёт
ровно одно имя — **`Link`**. Правило Dart отдаёт приоритет не-`dart:` импорту
без всякой диагностики.

**Сценарий (воспроизведено):**

```dart
import 'dart:io';
import 'package:ansi_escape_codes/ansi_escape_codes.dart';

void main() {
  final link = Link('build/latest');
  link.createSync('releases/1.2.3');
  stdout.writeln('${fgGreen}linked$reset ${link.path}');
}
```

```
error - The method 'createSync' isn't defined for the type 'Link'. - undefined_method
error - The getter 'path' isn't defined for the type 'Link'. - undefined_getter
```

**Последствия.** Это дословно тот отказ, который README сам называет и
объявляет исправленным (`README.md:236-244` про `Match`/`dart:core.Match`):
«failed with two errors that named no package». Пакет ориентирован на CLI, а
CLI почти всегда импортирует `dart:io`, где `Link` — символическая ссылка.
Слова `dart:io` нет ни в `README.md`, ни в `README.ru.md`, ни в `CHANGELOG.md`;

**Confidence: high** (воспроизведено компиляцией).

### M1. `Printer.write` без `writeln` теряет текст молча и навсегда

`lib/src/parsing/parser/printer.dart:508-541` — `_lineBuf` сбрасывается только


Класс объявляет `implements StringSink`. Контракт `StringSink` к flush не
обязывает, но здесь достать буфер нечем вообще. **Направление:** публичный
`flush()`, либо явная строка в дартдоке `write`. **Confidence: high**
(воспроизведено).

### M2. CSI SGR с приватным байтом не в первой позиции выводится дважды

`lib/src/parsing/parser/sgr_residual.dart:84-94` (`_isStatefulSgr`),
`lib/src/parsing/parser/entities/csi.dart:31-49` (`Csi._parse`),
`lib/src/parsing/patterns/patterns.dart:21` (`sgrPattern`).

Два независимых чтения «это stateful SGR?» расходятся: `Csi._parse` судит по
финальному байту `m` и при `FormatException` создаёт residual-операцию;
`_isStatefulSgr` судит по `sgrRe`, где класс параметров `[0-9;:]*`, тогда как
у парсера — `[\x30-\x3F]*`, то есть ещё `< = > ?`. Приватный байт **первым**
уходит в `CsiPrivate` и обрабатывается верно; **не первым** — создаёт
residual, о котором эмиттер не знает, и код пишется и буквально, и через
переигрывание.

```
<ESC>[?99mAB   substring(1) = B                      верно
<ESC>[1 mAB    substring(1) = B                      верно
<ESC>[1<mAB    substring(1) = <ESC>[1<mB<ESC>[0m     дубль
<ESC>[99;<mAB  substring(1) = <ESC>[99;<mB<ESC>[0m   дубль
<ESC>[1<mA     optimize     = <ESC>[1<m<ESC>[1<mA    дубль
```

Нарушен заявленный контракт байтовой верности (`Entity`: «writing them all out
in order gives the string back exactly as it came in»). Неизвестная
последовательность, отправленная терминалу дважды, может дать не тот эффект.
Затронуты `optimize`, `substring`, `Printer`; вставки — нет, они копируют
вход побайтно. Теста на этот случай нет, соседние два покрыты.
**Направление:** свести два чтения к одному — спрашивать не паттерн, а факт
наличия residual у куска. **Confidence: high** (воспроизведено).

### M3. `ESC 8` без `ESC 7` теряет `defaultStyle`; пакет читает свой вывод не так, как строил

`lib/src/parsing/parser/printer.dart:353-357` (`restoreFallback`), `:410`
(`changeDefaultsTo`), `lib/src/parsing/parser/pieces/parser_iterator.dart:200-217`.

При `RestoreCursor` без предшествующего сохранения модель откатывается к
`stateDefaults` и проецируется на `defaultStyle` — то есть принтер считает,
что default в силе. Но `ESC 8` копируется в вывод как есть, а `transitTo`
между «до» и «после» пуст, поэтому **ни одного восстанавливающего байта не
пишется**.

```
defaultStyle: Styles.bold, вход 'a\x1B8b'
written : <ESC>[0m<ESC>[1ma<ESC>8b<ESC>[0m
Parser этого же вывода:  a -> Style(bold)   b -> Style()      ← default потерян
контроль с ESC 7:        a -> bold  b -> bold  c -> bold      ← согласовано
```

Это не спор о поведении реального терминала: **`Parser` пакета читает
собственный вывод принтера иначе, чем принтер его строил.**
`test/printer_cursor_save_test.dart:55-64` покрывает случай, но только с
дефолтным `Printer()`, где проекция тождественна и разницы быть не может.
**Направление:** после `RestoreCursor` считать состояние терминала голым и
дать `transitTo` восстановить `defaultStyle` — либо задокументировать потерю
и привести модель к тому же. **Confidence: high** (воспроизведено).

### M4. Одна нераспознанная SGR даёт квадратичное раздувание в `substring`

`lib/src/parsing/parser/sgr_residual.dart:58-82` (`_advanceSgrResidual`),
`:119-138`, `:193-200` (`_operationsFromRoot`).

После первой нераспознанной SGR-операции в цепочку дописывается **каждая**
последующая, включая полностью известные, до настоящего полного reset. А
переигрывание идёт от корня при `fromResidual == null` — то есть на старте
каждого `substring` и каждой строки `Printer`.

Нарезка документа на строки, одна лишняя 11-байтная `\x1B[38;5;300m` в
начале, в потоке нет полного reset:

| строк | вход | выдано срезами | раздувание | время |
|---|---|---|---|---|
| 200 | 3 611 B | 105 900 B | ×29 | 29 ms |
| 800 | 14 411 B | 1 623 600 B | ×113 | 33 ms |
| 3200 | 57 611 B | **25 694 400 B** | **×446** | 498 ms |
| 3200 (контроль, без лишнего кода) | 57 600 B | 67 200 B | ×1.2 | 2 ms |

Триггеры реалистичны: `\x1B[38;5;300m`, `\x1B[38;2;300;0;0m`, параметры 56-58,
66-89, 98-120, `4:9`, переполненные числа.

**Оценка.** Механизм известен и принят: `docs/records/2026-08-14[4]` прямо
пишет «журнал неизбежно растёт… принимаемая цена выбранного полного
контракта», и обоснование корректно — известную операцию после неизвестной
выбрасывать нельзя. Но не покрыто записью то, что (а) `substring` даёт
квадратику **на одном вызове парсера**, а не только по строкам принтера, и
(б) в **публичном дартдоке** `substring`/`optimize`/`Printer` об этом ни
слова. Вход у такого пакета часто недоверенный, то есть это дешёвый
амплификатор. **Направление:** периодический flush через уже существующую
ветку `fromResidual != null && toResidual == null`, минимум — запись в
дартдок. **Confidence: high** (измерено).

### M5. Обратный обход `substring` квадратичен, и страж этого не меряет

`lib/src/parsing/parser/parser.dart:331-356` (`_pieceAt`), `:525-538`,

### M7. Переполнение в `tabs()` даёт неограниченный вывод в терминал

`lib/src/utils/tabs.dart:50-80`. `pos += tab` не защищено: значение около

**Направление:** проверять верхнюю границу либо считать `pos` с насыщением.
**Confidence: high** (воспроизведено).

# Architecture review

## Сильные стороны

**Разделение каналов.** Решение держать ссылку, SGR-residual и слот курсора
**рядом** с `State`, а не внутри — правильное и обоснованное. Ссылка не стиль:
`SGR 0` её не закрывает, она не вкладывается, её байты несут терминатор и
`id=`. Попытка запихнуть её в `State` дала бы четыре разных семантики в одном
типе. Обоснование записано (`docs/records/2026-08-07[1]`) и перепроверено мной
по коду — оно верно.

**`transitTo` как ядро.** «Писать разницу, а не сброс и всё заново» — это то,
из чего растут `optimize`, переоткрытие стиля в срезе и печать. Одна
абстракция обслуживает три поверхности, и перебор 199 809 пар состояний не
нашёл ни одного случая, где переход не восстанавливает цель. Это сделано
хорошо и должно остаться.

**Sealed-модель `Entity` + сохранение нераспознанного.** Разбор и обратная
сборка дают строку байт в байт; неизвестное не теряется, а едет в
`UnrecognizedEscapeCode`. Компилятор при этом обеспечивает исчерпывающий
`switch` (`no_default_cases: true` в `analysis_options.yaml:142` — правило,
которое делает эту гарантию рабочей, а не декларативной).

**Ленивость с явной ценой.** Дартдок `Parser` прямо говорит, что на большом
входе дешевле идти циклом по `pieces`, чем звать `length`. Пакет не
притворяется, что всё бесплатно.

**Пара «сканер + регулярка».** Байтовый `indexOf('\x1B')` дешевле прогона
regex-движка, и разделение «где может начаться» / «из чего состоит» —
разумный компромисс. Цена — механизм 7 из `architecture.md`: набор
байтов-открывателей живёт в шести местах и работает в конъюнкции. Это честно
задокументировано, включая признание, что перечень полным никто не доказывал.

## Слабые места и спорные решения

**Зонтичный вход слишком широк.** `ansi_escape_codes.dart` собирает всё — и
чистый разбор строк, и две функции, разговаривающие с настоящим терминалом
через `dart:io`. Следствия: потеря тегов Web/WASM (M6) и то, что самый
опасный код пакета (C1) втянут в самый рекомендуемый импорт. Разделение
«чистое ядро / платформенные утилиты» напрашивается, и в 3.1.2 оно де-факто
было.

**Две модели одного контракта в `SinkPrinter`.** Класс объявляет
`implements StringSink` и обещает переносить состояние между `write`, но
внутри `_prepare` каждый кусок обрабатывается как самостоятельная строка с
безусловным ведущим reset. Четыре канала переноса заведены (`_writtenLink`,
`_ambientLink`, `_owesTerminator`, `_savedCursor`), пятого — «незавершённый
хвост куска» — нет, и именно его отсутствие даёт H1. Архитектурно это не
дыра в замысле, а недоведённый до конца замысел: механика придержания уже
существует внутри `_prepare`, ей не хватает выхода за границу вызова.

**Два независимых чтения одного вопроса.** M2 — про то, что «это stateful
SGR?» спрашивается в двух местах двумя способами, и они расходятся на
подмножестве байтов. Это тот же класс, что механизм 7 из `architecture.md`
(шесть мест в конъюнкции), только здесь конъюнкция не сработала. Общий вывод
для пакета: **дублирующее чтение одного признака — самый дорогой паттерн в
этой кодовой базе**, и стоит завести правило сводить такие пары к одному
источнику, а не связывать их тестом.

**Непрозрачный residual без потолка.** M4 — принятое решение с корректным
обоснованием, но без ограничителя и без строки в публичном дартдоке.
Ветка, отпускающая непрозрачное состояние, в коде уже есть; она просто не
вызывается периодически.

**Асимметрия `ESC 8` и `CSI u`.** Первый откатывает состояние, второй
парсер называет, но состояние по нему не откатывает. Какая трактовка верна —
вопрос к владельцу; текущая пара несогласована.

## Архитектурные риски

1. **Поверхность 1648 имён неотзывна после публикации.** `Link` (H2),
   `debugForTest` (L3), `rgb` vs `fgRgb` (L6), форма `substring` (L2) — всё

2. **Модель «одна строка — один reset» плохо масштабируется на потоки.**

## Мутационная проверка: 16 из 18 неэквивалентных мутаций пойманы

19 мутаций внесены по одной в самые тонкие места (`_seamAt`, `_unfinished`,
`substring`, `transitTo`, быстрый выход `contains(ESC)`, `Stack`, RGB→256,
`Colors.byIndex`, `_renditionTransit`), каждая — полный `dart test`. Поймано
16, выжило 3, одна из выживших доказано эквивалентна (при `pos == start`
вырезаемая подстрока пуста, а весь блок вложен в `if (substring.isNotEmpty)`;
1140 дифференциальных вызовов `substring` — 0 расхождений). **Эффективный
mutation score — 16/18 = 89 %**, и это высокий результат для парсера такой
тонкости.

**Две выжившие мутации — настоящая дыра, и она в одном месте.** Обе границы
`_isIntermediate` (`lib/src/parsing/parser/parser.dart:1557`) не проверены
ничем. Проверено мной лично: обе границы сужены одновременно
(`>= 0x20 && <= 0x2F` → `> 0x20 && < 0x2F`), прогон на копии репозитория —
**`All tests passed! +915`**. Дифференциальный пробник против оригинала:

```
                оригинал                        мутант
a<ESC>SP   insertAfter(1,X) = aX<ESC>SP    →   a<ESC>SP X
           substring(0)     = a<ESC>SP<ESC>\ → a<ESC>SP
a<ESC>/    insertAfter(1,X) = aX<ESC>/     →   a<ESC>/X
           substring(0)     = a<ESC>/<ESC>\ →  a<ESC>/
a<ESC>!    (0x21, внутри диапазона)         одинаково в обеих сборках
a<ESC>.    (0x2E, внутри диапазона)         одинаково в обеих сборках
```

То есть корпус тестов бьёт по середине диапазона intermediate-байтов и **ни
разу по его краям** — `0x20` (SP) и `0x2F` (`/`), крайние члены по ECMA-48.
Последствие регрессии тихое и опасное: `insertAfter` вписывает
пользовательский текст **внутрь** незавершённой последовательности — `X`
становится финальным байтом `ESC SP X`, терминал его проглатывает и исполняет
непреднамеренную команду; `substring` перестаёт дописывать `ESC \`, и срез
уходит с открытой последовательностью, съедающей напечатанное следом.

## Критические риски, которые не проверяются

Все три High/Critical находки живы **потому, что оракул моделировал не то,
что происходит в реальности**. Это главный вывод раздела.

1. **`_FakeStdin` не моделирует настоящий `Stdin`** (`test/current_cursor_pos_test.dart`).
   Фейк — обычный `Stream`, у которого `cancel()` ничего не закрывает.
   Настоящий `Stdin` при отмене подписки закрывает fd 0. Непроверенный риск:
   **весь жизненный цикл терминальных режимов** — включение, восстановление,
   поведение при исключении. Это C1.

2. **CI гоняет примеры с `< /dev/null`** (`dart.yml:92-100`). Для
   `example/control.dart` это значит, что `stdin.hasTerminal` ложно и код
   выходит до интересного места. Непроверенный риск: **весь путь работы с
   настоящим терминалом** не исполняется ни разу нигде.

3. **Sink-принтер режется только по границам целых последовательностей.**
   В `test/printer_sink_test.dart` нет ни одного разреза внутри
   последовательности. Непроверенный риск: **корректность потоковой печати
   при произвольной границе куска** — то есть основной сценарий, ради
   которого sink-принтер существует. Это H1.

4. **`printer_cursor_save_test.dart:55-64` проверяет `ESC 8` без `ESC 7`
   только при дефолтном `Printer()`**, где `defaultStyle == terminalColors` и

   restore-fallback с непустым `defaultStyle`** — единственная комбинация, в

5. **Приватный байт CSI покрыт в первой позиции и не покрыт в остальных.**

# Performance and reliability

**Измеренное и здоровое.** ReDoS нет: 238 замеров по 17 патологическим
корпусам на 4 размерах входа дали отношения 1.71–2.55 при удвоении, ни одного
выше 3. Структурно тоже чисто — ни вложенных квантификаторов, ни пересекающихся
соседних классов; все четыре `RegExp` — константы времени компиляции, из
аргументов не строятся. Утечек нет: 400 000 строк через `SinkPrinter`
(35.8 M символов) — RSS плоский на 231.5 МБ. Удержание памяти на разбор —
262.1 байта на match, в откалиброванной полосе.

**Три реальные проблемы производительности** описаны выше: M4 (раздувание
×446 и квадратика от одной нераспознанной SGR), M5 (квадратика на обратном
обходе), M7 (неограниченный вывод при переполнении в `tabs`).

**Амплификация памяти на недоверенном входе.** Измерено: 80–120 байт RSS на
входной символ (`'\x1B' * n` — 119.3; обычный цветной лог — 87.6). То есть
10 МБ враждебного вывода → около 1.2 ГБ. Это неотъемлемое свойство
материализующего парсера, но ни README, ни дартдок об этом не предупреждают,
и дешёвый путь для недоверенного ввода (`ansiRemoveEscapeCodes`, работающий
`replaceAll` без построения дерева) как таковой нигде не назван.

**Конкурентность.** Настоящих race conditions нет: изолят однопоточный,
разделяемого мутабельного состояния между объектами нет. `runZonedPrinter`
создаёт принтер лениво и делит его на всю зону — при асинхронном теле зоны
логически независимые задачи будут переносить стиль друг другу через
`lastState`. Это следствие модели «принтер помнит, чем кончилась прошлая
строка», а не дефект, но в дартдоке не оговорено.

**Управление ресурсами.** Принтеры ресурсов не держат: `_SinkPrinterBase`
хранит только ссылку на `sink` и никогда её не закрывает. Закрывать нечего —
но и дописать нечем (M1). Единственная настоящая утечка ресурса в пакете —
дескриптор и режимы терминала в C1.

# Maintainability

**Сложность оправдана предметом.** Крупные файлы обманчивы: `ansi/csi.dart` —
2232 строки, из которых 2031 дартдок (91 %) вокруг 98 однострочных констант;
`ansi/colors.dart` — 789 из 796 строк внутри генерируемой зоны. Рукописного
кода в самых больших файлах почти нет. Реальные центры сложности —
`parser.dart` (1563), `styles.dart` (1636, генерируемый), `printer.dart` (752),
`state/style.dart` (781).

**Дартдок — сильнейший актив пакета.** Больше пяти тысяч строк, и он
объясняет не «что делает символ», а «почему так». Показательный факт: мой
фаззер выдал 7233 «падения» на суррогатных парах, и все до одного оказались
ошибкой моего оракула — поведение пакета (вставка не рвёт пару; половины,
между которыми стоит escape-код, остаются как лежат) описано в дартдоке
дословно, вместе с обоими случаями. Документация опередила тест.

**Строгость инструментов настоящая.** `strict-casts`, `strict-inference`,
`strict-raw-types`, `public_member_api_docs`, `comment_references`,
`close_sinks: error`, `cancel_subscriptions: error`, `no_default_cases`,
`lines_longer_than_80_chars` — около 120 правил поверх `package:lints`.
Единственный существенный пробел — выключенный `avoid_dynamic_calls`
(`analysis_options.yaml:40`); проверено запуском: вызов несуществующего метода
на `dynamic` проходит `--fatal-infos` молча. Плюс мёртвая конфигурация:
severity задан трём правилам, которые сами выключены (`:24,25,26`).

**Технический долг.** Мал и назван: три недостижимые ветки помечены в
комментариях как намеренный запас, дублирование parser ↔ extensions признано
в доках и подтверждено сходящимся на 60 000 входов. Настоящий долг — L8
(мёртвый параметр), L23 (15 % горячего пути на выбрасываемые аллокации) и
расхождения документации с кодом (L1, L9, L10, L18).

**Процесс.** 61 запись в `docs/records/`, живой `handoff.md`, разделение
«правила / состояние / история / бэклог» — устройство, которое реально
работает: я почти нигде не нашёл документа, врущего про код. Обратная
сторона — объём: 39 КБ CHANGELOG и 55 КБ README требуют дисциплины
синхронизации, которую ничто не проверяет (L19), и одно расхождение уже есть
(L1).

# Positive findings

Это стоит сохранить как есть.

1. **`State.transitTo` и вся модель состояния.** 199 809 пар — ноль
   расхождений, включая `CSI 22` для пары bold/dim, пять вариантов
   подчёркивания, `SGR 58/59` и суперпозиции.
2. **Байтовая верность разбора.** Сохранение нераспознанного через
   `UnrecognizedEscapeCode` — правильное решение, и оно держится (единственное
   исключение — M2, узкий подкласс).
3. **Дартдок.** Лучший, что я видел в Dart-пакете этого размера. Отдельно —
   разбор суррогатных пар и незавершённых последовательностей.
4. **Инфраструктура supply chain.** Actions пришпилены по SHA (все три
   сверены с тегами), `permissions: contents: read`, ни `pull_request_target`,
   ни кэша, ни секретов.
5. **Четыре независимых verification guard'а**, которые смотрят на разные
   свойства и не подменяют друг друга. `memory_guard` подделать пустой
   реализацией нельзя: якорь `_matchCount` падает при изменении корпуса или
   разбора, нижняя полоса ловит «парсер перестал удерживать разобранное».
   `generate.dart` сверяет registry с marker-зонами до первой записи.
   `check_entry_points` держит и замкнутость, и точный snapshot namespace, и
   свипает `lib/` на ошибки анализатора до обоих оракулов.
6. **Отсутствие ReDoS** — и структурно, и на 238 измерениях.
7. **Минимальная поверхность зависимостей:** одна рантайм-зависимость.
8. **Честность документации о пределах собственных инструментов.**
   `architecture.md` сам пишет, что перечень шести мест никто не доказывал
   полным, и сам называет класс мутаций, который сверка ответов не ловит. Это
   ровно та рамка, в которой находки этого ревью читаются как продолжение
   работы, а не как опровержение.

## Ответ на вопрос: готов ли пакет к публикации

**Нет.** Не потому, что он плох — по инженерному уровню он выше среднего для
pub.dev, и все формальные проверки он проходит честно, — а потому, что три
находки P0 либо вредят пользователю прямо (C1, H1), либо стоят мажорной
версии, если их не исправить **до** первого издания (H2, и туда же M6).

Формальные ворота зелёные и `pana` даёт 160/160 — это не опровергается, а
объясняется: находки лежат ровно там, куда ни один из существующих оракулов
не смотрит. Настоящий терминал подменён фейком, потоковая печать режется
только по безопасным границам, а столкновения имён с `dart:io` не проверяет
никто.

Минимальный набор до публикации — **C1, H1, H2 плюс решение владельца по
M6**. Это порядка трёх-четырёх дней работы вместе с тестами, которые не дадут
этим дефектам вернуться. Всё остальное можно издавать следом.
