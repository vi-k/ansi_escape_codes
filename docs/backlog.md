# Бэклог

Рабочий бэклог пакета. Пункт, взятый в работу, уходит в спеку в
`docs/records/` (формат имён — `YYYY-MM-DD[N]-<тема>.md`) и
вычёркивается отсюда; сделанное живёт в CHANGELOG, а не здесь.
Состояние пакета целиком — в `docs/handoff.md`.

Из волны вставки рядом с незавершённой последовательностью
(`docs/records/2026-08-11[2]-insert-unfinished-sequence-design.md`):

- `ESC P` (DCS), `ESC X` (SOS), `ESC ^` (PM) и `ESC _` (APC) парсер
  читает как завершённые двухбайтовые escape, а стандарт — как открытие
  строки, идущей до `ST`. Терминал съест написанное за ними так же, как
  съедал текст за незавершённым `OSC`:

      Parser('aa\x1BP').insertAfter(2, 'X')
      // 'aa\x1BPX' — для пакета плоский текст 'aaX', для терминала
      // 'X' уже часть device control string

  Правка — в модели разбора, а не во вставке: она меняет чтение любой
  строки с этими кодами (плоский текст, длину, срезы, печать, вставку),
  и поэтому отдельным заходом. 8-битные C1 (`0x9B`, `0x9D`) пакет не
  распознаёт вовсе — читает как обычный текст; это тот же вопрос про
  модель разбора.

Остальные пункты бэклога взяты в работу волной
`docs/records/2026-08-05[11]-backlog-wave-plan.md` и закрыты ею; два
следующих — сдвинутый `lastState` у `prepare` синка и два имени,
говорившие об одной повинности из двух, — волной
`docs/records/2026-08-11[1]-backlog-tail.md`; а четвёртая поверхность
незавершённой последовательности, из-за которой вставка теряла текст, —
волной `docs/records/2026-08-11[3]-insert-unfinished-sequence-plan.md`.
